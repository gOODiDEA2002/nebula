# 向量库选型与块 ID 映射

## Chroma 与 Qdrant 的取舍

Nebula RAG 的向量写目标通过 `VectorStoreService` 抽象，底层可切换 Chroma 或 Qdrant。

- Chroma：部署轻量，适合本地开发与示例验证；不提供集合别名机制，蓝绿重灌需要业务侧自行切换集合名。
- Qdrant：支持集合别名，配合 R3 版本化重灌可做到检索不中断的蓝绿切换；生产推荐。

## 块 ID 的确定性映射

索引管线对每个块强制确定性 ID 策略：`<文档 ID>#<块序号>`，例如 `nebula-faq-vector#0`。

确定性 ID 带来三个好处：

1. 同一文档重复灌库，块 ID 稳定，向量库按 ID 覆盖即幂等。
2. 多路检索（向量路与关键词路）用同一套块 ID 对齐，融合去重可靠。
3. 金标评测按文档级前缀判中，块级变动不影响命中口径。

## 更换 embedding 模型的影响

向量由 embedding 模型产生，更换模型后旧向量不可比，必须重灌全部文档。示例把切块参数掺入 contentHash，改切块参数即触发重灌；换 embedding 模型则需手动清库重灌。

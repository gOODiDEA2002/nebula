# 网关模块

网关是所有外部请求的第一跳，承担路由、鉴权、限流三件事。三件事的执行顺序固定，不接受按站点调整，因为顺序一旦可配就会有人把鉴权排到路由后面，然后在某个灰度环境里放行了本该拒绝的请求。

## 路由匹配

匹配按前缀优先、精确优先的顺序进行，两条规则冲突时长的那条胜出。匹配结果会被缓存，缓存时长可配，默认三十秒。改了路由之后最长要等一个缓存周期才生效，这一点在演练时经常被误判成配置没生效。

## 限流

限流有三种可选算法，它们的差别不在于能不能限，而在于面对突发流量时的形状：一种允许短时突发，一种把流量削成绝对平滑，一种介于两者之间。选型时先问业务能不能接受突发，再谈参数。

### 令牌桶

它允许积攒额度，因此天然支持突发。空闲一段时间之后，积攒下来的额度会在瞬间释放出去，这既是它的优点也是它最容易被误用的地方。

#### 适用场景

适合请求量本身不均匀、但下游有富余处理能力的接口。典型的是后台管理类接口：平时几乎没人用，一到月底集中导出，允许它把攒下来的额度一次用掉反而是好事。反过来，如果下游是一个吞吐固定的外部渠道，突发只会把对方打挂，那就不该选它。

#### 参数说明

两个参数决定行为：一个决定长期的平均速率，一个决定能攒多少。前者定的是稳态吞吐，后者定的是允许多大的瞬时爆发。两个参数要一起调，只改一个通常得不到预期效果。生产上最常见的错误是把第二个参数设得过大，结果稳态限住了、突发却能把下游打穿。

#### 默认值

补充速率默认每秒二百个，桶容量默认四百个，突发上限等于桶容量。

#### 常见误用

把容量设成速率的十倍以上，等价于给下游留了一个十秒的无保护窗口。评审时对超过三倍的配置一律要求给出下游承压证明。

### 漏桶

它不允许积攒，输出恒定平滑，代价是突发请求只能排队或被拒。适合下游吞吐固定的场景。

## 相关模块速览

- 模块端口表里的默认超时列给的是各模块单路调用的超时上限，端口一旦分配就不再回收。
- 配置键表里的默认值与是否必填两列最容易被混淆，不启用对应能力时整行都不生效。
- 错误码表里的是否可重试一列决定调用方该退避重试还是直接返回，错误码分配后不再复用。
- 示例检索器在构造期校验权重不能为负数，检索期把单路失败收敛成空表，并用超时方法给出本路自己的毫秒数。
- 管线装配代码里检索器列表为空要当成配置事故抛异常，候选放大倍数与上下文预算都写死在装配处，构造器参数一个都不能少。
- 消费者代码里反序列化失败直接进死信，幂等判断放在业务处理之前，可重试异常抛回队列由消息模块统一重投。
- 本地缓存的过期策略与最大条目数共同决定内存占用，过期时间必须短于远端那一层，否则会出现旧值窗口。
- 搜索索引的分词器下发时机决定词典更新之后能不能生效，写入端与查询端必须用同一套，不一致会出现写进去却搜不到。
- 对象存储分片上传的阈值与每片大小决定重传代价，分片会话过期之后已传的片会被清理，必须重新发起。
- 应用配置文件把各分组的键放在同一棵树下，键路径决定了它属于哪个分组，叶子键名在不同分组里可能重名。
- 检索器注册表里每一路都带权重、超时毫秒与开关，融合分组另外带融合常数与候选放大倍数。
- 索引记录行里每条都带模块、动作、重建次数与状态，失败的那几条要按备注里的处理建议重跑。

## 相关配置键名

下列叶子键名在多个分组里出现过，只看键名无法判断它属于哪个分组：

- `refill-per-second`
- `capacity`
- `max-entries`
- `expire-seconds`
- `multipart-threshold-mb`
- `part-size-mb`
- `timeout-millis`
- `rrf-k`
- `candidate-multiplier`
- `rebuild-count`
- `status`
